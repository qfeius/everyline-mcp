# everyline-review-config（MCP）

业务流程以 everyline-cli release v1.1.1（`617a2cc47aa208cbc651412003b763afe4c55c41`）的原版配置 Skill 为基线，保留对象查询、逐项变更确认、完整集合、规则内容约束、归属与删除影响核对及写后回读；调用和授权适配为当前 EveryLine MCP。

每个新会话首次维护配置前，以 `{}` 调用当前连接器的 `read-review-config-skill`，读取完整部署正文；当前正文已经由该工具返回时不重复调用。配置操作共用 `read-review-skill` 中的执行前检查、连接器与身份、状态恢复和通用边界；首次需要公共接入时读取它，配置目标仍由本 Skill 推进，不进入合同上传或审查流程。连接器承担 OAuth，不依赖本地 CLI、Profile 或跨 Skill 文件路径。工具缺失时处理目标连接器的启用、授权或刷新，保留原目标，不转到其他产品。

## 触发边界

在用户明确要求以下任一事项时使用：

- 查询、创建、重命名、重新配置或删除审查清单；
- 查询、创建、编辑、调整所属分组或删除审查规则；
- 查询、创建、重命名或删除规则分组；
- 查看规则归属、清单引用或删除影响。

以下事项不使用本 Skill：

- 在一次合同审查中选择已有清单；该步骤属于 `everyline-review`；
- 发起、继续或查询合同审查任务；
- 合同起草、一般法律咨询或其他合同 MCP 操作。

不要因为用户浏览过某个对象就推断其同意修改。查询不授权写入，一次确认也不能沿用到另一个对象或另一种操作。

“新建或修改清单后审查合同”先按本 Skill 完成具体写入确认、写入与回读，再携带真实清单 ID 和已确认业务输入转回 `everyline-review`；发起审查的请求本身不代表用户确认配置写入。

## 运行时就绪检查

用户指定 `everyline-cli-mcp-test` 时，配置操作与授权恢复始终使用该连接器的宿主 OAuth。宿主未暴露授权操作时引导至该连接器设置；不加载通用 `auth` 或 `contract-cli-*` 技能，不探测或执行 `contract-cli` / `everyline-cli-mcp` 命令，不使用本地 Profile 代替连接器身份。

每次会话首次进入时，核对当前连接器提供本 Skill 所需工具并读取其 Schema。固定连接器、当前用户与租户，后续查询、写入和回读复用同一上下文。首次使用展示实际 Skill 版本和已知 MCP 版本，缺失值写“未知”，不重复展示或编造最新版本。

独立配置任务在查询或单次已确认写入及回读完成后处理已知更新；组合任务还需等后续审查取得终态、结果已获取且整条流程结束，避免两个阶段之间切换连接器或 Skill。授权失败先恢复同一连接器身份，再核对原对象和上一步结果。用户要求退出或切换账号时立即停止配置调用，由宿主管理旧授权，切换账号再通过同一连接器重新授权；不调用 MCP 退出接口。恢复前核对用户、租户和原对象权限，不在新租户下自动重放原配置写入。

每次写入前查看当前工具的参数和说明，工具操作必须具备以下条件：

1. 查询结果能返回真实对象 ID、类型、归属和关联关系，并可读取全部分页；
2. 清单结果能可靠区分内置与自定义，并返回重新配置所需的完整规则集合；
3. 更新工具能表达用户要求的完整最终状态；
4. 删除规则或分组时，MCP 能完整返回引用与级联影响，并提供服务端原子删除能力；
5. 调整规则分组时，MCP 提供单次原子变更能力；
6. 工具能输出可解析的结构化结果。

任一必要能力缺失时，明确说明“当前 MCP 版本未支持本次配置操作”，列出缺失能力并停止写入。可以继续适用的只读查询；不得改用未注册接口、通用网络命令、自行构造网络请求或多次写入模拟目标能力。

本 Skill 沿用 release 的单项操作流程。实际调用使用当前工具 Schema，业务参数直接放在 arguments 顶层，无筛选查询传 `{}`，不用旧 `input` 包装：

| 对象 | 查询 | 创建 | 更新 | 删除 |
| --- | --- | --- | --- | --- |
| 清单 | `list-review-checklists` | `create-review-checklist`，传 `data` | `update-review-checklist`，传 `id`、`data` | `delete-review-checklist`，传 `id` |
| 分组 | `list-review-rule-groups` | `create-review-rule-group`，传 `data` | `update-review-rule-group`，传 `id`、`data` | `delete-review-rule-group`，传 `id` |
| 规则 | `list-review-rules`，传 `groupId` | `create-review-rule`，传 `groupId`、`data` | `update-review-rule`，传 `groupId`、`ruleId`、`data` | `delete-review-rule`，传 `groupId`、`ruleId` |

删除工具存在不代表级联条件已满足；仍须通过真实结构化结果与接口说明确认引用枚举和原子语义。连接器中已有批量工具保留，但本 Skill 不调用批量创建、批量更新或批量删除，也不把单项授权扩大为批量。

### 当前接口的字段与能力边界

- 清单列表只支持 `name`、`sort`、`pageIndex`、`pageSize`；分组和规则列表支持分页排序，规则查询还需 `groupId`。从第 1 页开始读取，不传未声明的启用状态、分类、阶段、时间或人员筛选。
- `data` 表达完整最终字段：清单使用 `name` 和非空 `reviewRuleIds`；分组使用 `name`；规则使用 `name`、`riskLevel`、`content`，选填 `riskTips`。单项 ID 只放外层路径参数，不重复放入 `data.id`。所有 ID 均保持原始字符串。
- 清单创建和更新会写入 `enabled=true`、`reviewStage=[30,3]`、`contractCategory=["-1"]`。重命名或更新集合前读取并核对这三项，仅当前值与默认值一致时继续；字段缺失或不同则停止，说明接口会重设元数据，不声称未修改字段得以保留。
- `generationMode`、名称、创建人等业务属性不替代内置/自定义或只读类型的权威证据。类型不明、只读或内置对象停止相关写入。
- 分页取全只证明当前可见集合完整，不证明全部引用可见。当前没有完整影响快照、条件版本写入或原子移动工具；不添加 `expectedRevision`、`impactToken`、`onlyIfEmpty` 等未声明参数。
- 分组删除没有“执行时仍为空才删除”的条件保护。仅授权删除空组时停止；查询时为空不等于执行时仍为空。规则、非空组删除同样需要完整影响及单次原子删除证据，缺证据时停止，保留下面的业务核对流程。
- `groupId` 是规则原所属分组的路径参数，不通过改路径调整归属，也不以复制新规则、改清单、删除旧规则模拟移动。

## 通用执行协议

### 读取与定位

1. 核对业务 `code=200`（数字或字符串）且没有 `success=false`，再读取响应中的结构化 `data`；宿主已解包时按实际结构读取。工具或 HTTP 成功不单独证明业务成功。
2. 查询存在分页时持续读取，直到服务端明确表示没有下一页；不能把第一页当作完整集合。
3. 用本次查询得到的真实 ID 操作，不复用其他身份、历史会话或旧截图中的 ID。
4. 名称不唯一时，展示名称、ID、类型或所属分组等真实可区分信息，让用户选择。
5. 不能唯一定位、不能确认类型或不能取得完整关联时停止，不猜测。

### 写入门槛

创建、更新、调整归属和删除均按以下顺序执行：

1. 读取目标对象最新状态和所有受影响关系。
2. 向用户展示准确对象以及将发生的变化；更新使用“修改前 → 修改后”，集合变化分别列出“新增”和“移除”。
3. 明确询问是否执行这一次具体写入，并等待用户确认。用户未确认、确认含糊或改变目标时不执行。
4. 确认后立即重新查询目标及关联。状态变化时重新计算差异和影响，再次展示并取得新确认。
5. 按同一份最终请求逐项校验当前 Schema。当前 MCP 没有独立预检工具，不附加虚构的 dry-run 参数，也不通过正式写入做预检；宿主校验通过不等于写入成功。
6. 只调用一次与用户确认内容一致的单项写工具。删除时在前述门槛均满足后提交当前工具声明的参数；原 CLI 的 --yes 由本次真实用户确认承接，不向 MCP 添加 yes 或 confirm 字段。
7. 写入返回后重新查询目标及关联，验证真实最终状态；不要只根据工具调用成功、进度文本或预检结果宣布成功。

用户已明确确认当前具体对象、完整变更及影响且范围未变时，复用这一次有效授权，不重复询问；新增对象、改变字段或扩大影响时重新展示并取得确认。

请求体以结构化 JSON arguments 传递，单项完整对象放在 `data` 中。不要把用户内容拼进 shell，不调用任何批量工具。操作结束后仅清理本流程创建的临时文件。

### 结果表达

- 查询成功：展示用户需要的对象名称、类型、ID、归属和关联，不输出无关响应体。
- 写入成功：展示实际变更、真实对象 ID 和回读后的最终状态。
- 写入结果未知：说明最后已确认的状态和真实错误，不盲目重试；先回读再决定是否继续。
- 权限或授权失败：保持当前身份，进入 `everyline-review` 的授权恢复流程；不得自动换成另一身份。
- 服务端拒绝：返回真实原因和 MCP 实际提供的请求标识，不包装成成功。

## 审查清单

### 查询清单

使用已注册的 `list-review-checklists`，读取全部分页。每个清单至少展示：

- 名称和真实 ID；
- 内置或自定义类型；
- 当前包含的规则名称及真实 ID。

结构化结果无法区分类型或只返回部分规则时，不执行后续写入。内置清单仅可查询或由审查流程选择，禁止重命名、重新配置或删除，即使底层工具没有主动拦截也不得尝试。

### 创建自定义清单

1. 收集清单名称。
2. 完整查询全部规则分组及其规则。
3. 让用户选择最终包含的规则；名称重复时同时展示分组和 ID。
4. 展示“新建自定义清单”的名称以及最终规则集合并取得确认。
5. 按当前 Schema 生成完整 `data`，包含名称和最终 `reviewRuleIds`，调用已注册的 `create-review-checklist`。
6. 回读新清单，核对名称、类型和完整规则集合。

不得把未查询到的规则名称转成猜测 ID，也不得创建内置清单。

### 重命名或重新配置自定义清单

1. 唯一定位自定义清单并读取当前名称、完整规则集合。
2. 重命名时展示旧名称与新名称。
3. 重新配置时完整查询可用规则，让用户给出最终规则集合。
4. 计算并展示保留、新增和移除的规则；没有变化时不调用更新。
5. 用户确认且复查无漂移后，使用 `update-review-checklist`，传真实 `id` 与完整 `data`，一次提交最终状态。
6. 回读并逐项核对名称和规则集合。

不要把“增加一条规则”实现为覆盖未知的部分集合；未取得当前完整集合时停止。

### 删除自定义清单

1. 唯一定位目标，确认结构化类型为自定义。
2. 展示清单名称、ID、包含的全部规则及 MCP 返回的其他影响。
3. 明确询问是否删除这个清单。
4. 用户确认后重新读取；目标或影响变化时重新确认。
5. 只有当前工具 Schema 与说明确认删除能力且本次用户确认已完成时，执行单项 `delete-review-checklist`，传真实 `id`。
6. 回读并确认目标已经不存在；同名但不同 ID 的清单不得视为已删除。

## 审查规则

### 查询规则

先完整查询规则分组，再对每个相关分组读取全部规则分页。展示规则名称、真实 ID、所属分组、风险等级，以及用户要求的内容。需要判断引用时，还必须取得每条规则被哪些清单引用的完整集合。

### 创建规则

1. 让用户从实际存在的规则分组中选择一个目标分组。
2. 收集并校验：
   - 规则名称：必填；
   - 风险等级：必选“红线 / 高 / 中 / 低”之一；
   - 审查逻辑：必填，最多 3000 字；
   - 风险说明：选填，最多 1500 字。
3. 展示分组、规则名称、风险等级、审查逻辑和风险说明的完整摘要。
4. 用户确认且分组仍存在后，调用已注册的 `create-review-rule` 单项工具。
5. 回读并核对真实规则 ID、内容和所属分组。

不得新建一个近似分组来代替用户选择，也不得把非法风险等级自动改成最接近的值。

### 规则字段的 MCP 映射

用户看到的风险等级与工具值按以下确定映射转换，不把原始数字当作选项名称：

| 用户等级 | 平台等级名 | `riskLevel` |
| --- | --- | --- |
| 红线 | 致命风险 | 3 |
| 高 | 重大风险 | 2 |
| 中 | 警示风险 | 1 |
| 低 | 建议优化 | 0 |

审查逻辑写入 `content`（最多 3000 字），风险说明写入 `riskTips`（最多 1500 字）；完整保留用户确认的原文，不自动截断、改写或把非法等级改成最接近值。规则名称按工具约束为 1～150 字，清单与分组名称为 1～50 字。编辑只改变已授权字段，其余完整保留；清空选填字段时显式传空字符串并按后端回读核对，不用省略字段猜测清空语义。

### 编辑规则

1. 通过“分组 + 规则”唯一定位并读取完整当前内容与清单引用。
2. 只修改用户明确提出的字段，未修改字段保持原值。
3. 按创建规则的约束重新校验最终内容。
4. 展示逐字段的修改前后差异；没有变化时不调用更新。
5. 用户确认且复查无漂移后，调用已注册的 `update-review-rule` 单项工具。
6. 回读并核对所有字段和引用关系。

### 调整规则所属分组

1. 唯一定位规则、当前分组和用户选择的真实目标分组。
2. 展示“当前分组 → 目标分组”、规则 ID，以及该规则被引用的全部清单。
3. 只有当前工具 Schema 与说明确认 MCP 支持单次原子调整归属时才取得确认并执行；不能用“复制新规则、改清单、删除旧规则”模拟。
4. 确认后重新查询规则、两个分组和引用；任一变化都需要重新确认。
5. 执行一次原子变更，随后回读规则归属与全部引用。

### 删除规则

1. 唯一定位规则，读取完整内容、所属分组和全部清单引用。
2. 展示规则名称、ID、所属分组、所有受影响清单，以及将解除的每一条关联。
3. 明确询问是否按该级联范围删除规则。
4. 用户确认后重新读取规则和全部引用；引用有任何变化时展示新影响并重新确认。
5. 只有 MCP 明确提供“解除全部引用并删除规则”的单次原子操作时，才执行带显式确认的单项删除工具。
6. 回读规则、原分组和受影响清单，确认规则不存在且引用已全部解除。

不得先逐个更新清单再删除规则。无法完整枚举引用、原子能力不可用或用户未确认时，不解除任何关联，也不删除规则。

## 规则分组

### 查询、创建和重命名

- 查询：使用 `list-review-rule-groups` 读取全部分页，并读取每个分组下的全部规则。
- 创建：收集分组名称，展示准确名称，取得确认后调用 `create-review-rule-group`；回读真实 ID 和名称。
- 重命名：唯一定位分组，展示“旧名称 → 新名称”，取得确认并复查后调用 `update-review-rule-group`；回读验证。

名称重复时展示真实 ID 让用户选择，不替用户合并分组。

### 删除规则分组

删除分组会影响其规则以及引用这些规则的清单，按高风险级联操作处理：

1. 唯一定位分组，读取分组下全部规则。
2. 对每条规则读取全部清单引用，汇总分组、规则和受影响清单的完整级联范围。
3. 向用户展示分组名称与 ID、将删除的全部规则、将解除的全部清单引用，并明确询问是否执行。
4. 用户确认后重新读取全部对象；分组、规则或引用变化时展示新范围并重新确认。
5. 只有 MCP 明确提供覆盖上述范围的单次原子级联删除时，才执行带显式确认的 `delete-review-rule-group` 单项工具。
6. 回读分组、规则和受影响清单，确认删除与解绑均已完成。

不得拆成逐条删规则、逐个改清单和最后删分组。服务端无法保证原子性、影响范围不完整或用户未确认时，停止且不产生任何变更。

## 安全与真实性红线

- 只调用当前连接器工具清单中已注册的 EveryLine MCP 工具；禁止裸 API、内部地址和自行拼接 HTTP 请求。
- 不输出或记录任何凭据、Token、Cookie，也不把合同或规则内容发送给流程外服务。
- 不猜测对象 ID、类型、归属、引用关系、级联结果或权限。
- 不执行批量创建、批量更新或批量删除。
- 不在用户确认前写入，不把预检或工具调用成功描述为业务写入成功。
